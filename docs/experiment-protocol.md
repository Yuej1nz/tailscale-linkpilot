# Tailscale 打洞优化实验规程

版本：设计稿 1，2026-10-02。用于验证优化是否改善原版，并区分临时探测通路、实际业务直连、长期保持和故障恢复。本规程尚未执行。

## 需要回答的问题

- 双向协调是否比原版同预算探测更有效？
- 成功主要来自新的本地端口、重启、临时预热，还是它们的组合？
- 同一 socket 内探测和业务通信是否比临时进程交接更可复现？
- 收益能否在新的 NAT 状态、不同设备和至少两种受控困难拓扑上重复？
- 新增尝试是否损害已有直连、多对端业务或失败后的可用性？
- 官方是否已经观察、发布并尝试过本次成功的候选？差异在候选覆盖、探测时序、数据路径还是结果判断？

校园多出口问题作为真实场景案例，不能等同于所有对称 NAT 或全部教育网。公网地址随目的地变化是一项观测，不能单靠它推断完整映射和过滤行为。

## 实验组

| 组 | 动作 | 主要比较 |
| --- | --- | --- |
| A0 | 官方原版，固定业务与测量计划 | 自然建立基线 |
| A1 | 原版加同端口服务重启，其他条件不变 | 分离重启的影响 |
| A2 | 原版加新端口与相同重启流程，不预热 | 与 A1 比较端口影响 |
| A3 | 两端通过各自 Tailscale 接口按约定窗口发起探测，不临时接管 | 与 A0 比较协调调度影响 |
| A4 | 新端口临时预热、严格往返、同端口接管 | 与 A2 比较预热影响 |
| A5 | 扩展版同 socket 策略 | 仅在 P3 实现后，与匹配的原版及 A4 比较 |

官方探测接口自身可能触发建链，不能把 A3 称为纯观察。控制组和实验组必须使用相同的结果测量时点；额外诊断探测的数量计入组别动作和流量。

另设候选筛选子实验 C0／C1：固定本地端口、发送预算、业务负载和轮次，仅比较官方候选筛选与加入新鲜低置信候选的筛选策略。C1 不得获得 C0 无法访问的新探测服务器或额外探测预算；记录相同原始观察池中每个候选的保留／淘汰原因。需要新增观测才能得到地址时，另立实验比较，不混入筛选结论。该实验须在取得原始 netcheck 观察与原版候选尝试证据后实施，现有外挂无法访问时应列入 P3 最小观测扩展。

保持软件版本、硬件、接口、对端、业务负载和拓扑一致。A1／A2 的时间预算包含服务重启，A4 包含预热及接管，总建立窗口均为 120 秒；成功后的验证窗口独立计时。动作组合仍可能存在交互作用，不能仅靠此表声称某一因素具有唯一因果。

## 独立试次和公平性

1. 在隔离 VM／路由器／网络命名空间中运行；不清空共享主机或生产路由器的连接表。
2. 每轮重建指定 NAT／过滤状态和客户端状态到共同起点，保存随机种子、配置摘要和版本。不能只换源端口就宣称所有旧状态已清除。
3. 同一条件内随机交错执行各组；同一客户端实例不并发参加不同组，防止互相保活。
4. 保留完整失败、无效试次及其理由。只有预先定义的环境故障可以标为无效；直连失败不是无效试次。
5. 真实校园、家庭和移动网络不能确认上游状态清除时，标为相关实地样本，按网络／设备／日期分组统计。
6. 预跑每组每个关键拓扑 10 次用于排错，不用于最终优越性结论。正式主要拓扑每组至少 100 次；在正式采样前冻结样本量、比较组和停止规则。

原版端点默认不能识别自定义回显。预热实验需要两端本地助手或实验扩展配合，不能复制历史 raw socket 响应器并视作普通跨平台能力。

## 直连成功判据

三个层次分别记录：

1. **候选有效**：属于本轮网络代次、接口和身份；随机挑战请求确实收到匹配回显。主动推送来的任意包不算往返。
2. **Tailscale 路径有效**：真实 Tailscale 探测返回当前 direct 端点，排除 DERP 和 peer relay。证据有时间、探测类型和节点身份，过期状态不算。
3. **业务有效**：通过 Tailscale 承载的认证测试服务完成双向挑战与数据校验，并在同一时间窗核对实际业务路径。

120 秒内进入第 3 层后，继续观察 60 秒：在 0、20、40、60 秒完成同样的业务验证并确认路径。期间发生中继或断连，记为“曾建立直连但未保持”，不算主要成功指标。探测成功和业务可达都不能单独证明整段业务数据未走中继。

受控实验优先用两端物理接口抓包、业务时序与路径信息交叉核对；增强版增加实际数据路径事件。生产兼容版无法证明全部业务路径时，报告证据等级，不能宣称严格验证通过。多路径过渡期间应标明混合路径。

公网 IPv6 验收额外要求：外层实际 UDP 是 IPv6，两端处于不同受控网络，并有路由或拓扑证据。仅 GUA、局域网 IPv6、tailnet IPv6、隧道内 SSH 成功均不满足该判据。

## 网络与平台矩阵

| 类别 | 要覆盖的条件 | 关注点 |
| --- | --- | --- |
| 基础直连 | 同 LAN、至少一端公网入口、容易打洞的双 NAT | 不退化，不把 LAN 成功当公网成功 |
| 映射与过滤 | 端点无关／目标相关映射，独立改变地址及端口过滤 | 将映射和过滤分开描述，验证模拟器实际行为 |
| 多层 NAT | 内外层分别控制映射，CGNAT 形态 | 不能把内层 UPnP 成功当全路径成功 |
| 多出口 | 同源端口按目的地选择不同公网出口 | 候选观察点、有效期和路由一致性 |
| IPv6 | 可用双向 IPv6、仅出站状态允许、黑洞 IPv6 | 正确回落与单独的公网 IPv6 结果 |
| 无可用 UDP | 明确阻断外层 UDP，但 DERP 可用 | 预算结束后诚实报告，继续保持中继可用 |
| 多网卡与代理 | Wi-Fi／有线、额外 VPN／TUN、重叠私网 | 路由与源接口一致性，避免诊断走另一出口 |
| 平台组合 | Linux↔Linux、Windows↔Linux、macOS↔Linux | 同版本优先；不同版本单独标识 |
| 客户端组合 | 官方↔官方、助手↔官方、增强↔官方、增强↔增强 | 原版兼容和能力降级 |

只对实际搭建并验证的映射／过滤行为命名；单纯使用 Docker NAT 不能宣称已经模拟全部困难 NAT。物理路由器和真实移动网络的实测单独列出。

## 保持和恢复

已有直连上覆盖网络断开重连、换 Wi-Fi、源地址变化、客户端服务重启、设备重启、休眠唤醒、路由器状态清空、对端退出及助手崩溃。

每类故障至少 20 次，记录故障起点、网络恢复时刻、业务恢复时刻、恢复直连时刻、回退结果。网络本身不可用的时间与优化器恢复耗时分别统计。

长期测试持续 24 小时，至少含 5 分钟和 30 分钟无额外诊断／业务流量的空闲段，再由真实业务重新发起。原版自己的保活仍可运行，必须记录；不把休眠阶段持续 ping 得到的结果称为自然保持。

另测连续两次服务崩溃、变更中掉电、协调连接丢失、多用户重复请求、第三方并发改配置、原版自动升级及磁盘写入失败。验证设备锁、持久计划和回退机制能收敛，不留下持续重启循环或无限尝试。

## 统计与发布门槛

每个拓扑分别输出首次成功数／全部有效试次数、120 秒窗口内累计成功率、保持通过率、建立耗时分布、恢复耗时分布、中继占用、丢包、业务吞吐、额外探测包数和服务重启次数。耗时同时展示失败和超时，不能只统计成功者后宣称整体更快。

比率给出置信区间；组间差异按实验设计估计，不把相关实地样本视为独立二项试次。诊断代码故障、环境无效试次、路径建立失败分别公开。统计方法和主要比较在正式试验前冻结。

以下为发布门槛提案，P0 固定后才开始正式比较：

- 路径与业务分类夹具全部通过；实际验证不得把中继或临时探测当真实直连。
- 崩溃／断线回退用例全部通过，配置冲突可报告且不会覆盖他人修改。
- 主要困难拓扑上的直连成功率有可重复提升：至少两种受控拓扑，预先指定比较的差值 95% 置信区间下界大于零；多重比较在分析计划中处理。
- 简单拓扑成功率相对原版下降不超过 2 个百分点，以预先规定的非劣检验确认；最低 100 次可能不足，样本量必须按功效估计增加，不能直接凭点估计过关。
- 连通性、恢复和额外开销同时报告；若收益仅出现于少数拓扑，则按条件启用该策略，不宣称通用改进。

## 证据与失败原因

每次保留 manifest、before、events、after、业务结果和必要的受限抓包；记录构建 commit、客户端发行形态、工具链、策略版本、网络配置摘要、随机种子、各动作起止和配置事务。对外导出脱敏，本地原始记录设最小访问权限。

原因至少区分：权限不足、能力不支持、对端不可达、协调失败、候选过期、探测超时、业务失败、路径证据不足、预算耗尽、回退失败、配置冲突。只有受控故障注入或其他直接证据才标“已确认 UDP 阻断”；普通公网超时标“原因未确定”。
