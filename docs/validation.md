# 验收范围与结果

验证日期：2026-10-03，Asia/Shanghai。当前产品版 `0.6.0-macos-agent`，兼容核心版本 `0.4.0-windows-client`。原始部署配置、实际地址、节点 ID、账号与完整报告保留在本机，公开仓库只记录范围及结论。

## 实机结果

| 组合 | 已证明的结果 |
| --- | --- |
| Windows amd64 → Linux amd64 | 用户计划任务运行；真实中继状态下，无新增立即优化请求，由后台触发新会话并完成三次业务验收；辅助会话保留与续期 |
| macOS arm64 → Linux amd64 | 用户 LaunchAgent 与独立受限采集授权；无新增立即优化请求，由持续中继触发新会话；三次业务及承载计数全部通过 |
| Mac 后台重启 | 同一辅助会话继续运行，成功报告与已处理请求保留；独立探测仍为 direct；默认租期在满足条件时续期 |
| Linux 多设备协调 | Mac 与 Windows 授权隔离，授权撤销和恢复无需重启整个服务 |

Mac 自动试次结果为 `direct_via_new_local_session`。前两个候选没有证明 UDP 往返，关闭且未启用原生转发；第三个候选成功。三次数据大小均为 64 KiB，双方原生路径和两端加密业务计数通过。后续客户端独立探测约 12 ms；服务端探测仍有时延波动。

原有手动工具曾先建立健康直连。产品的保留验收记录 `optimized=false`，随后只清理这对设备的旧辅助会话，重新确认中继，再验证新产品自动恢复。这两个阶段分别记录，不把已有直连算作新打洞成果。

## 已修复问题

- Windows 计划任务的 Job 不允许子进程脱离，旧独立 worker 启动返回 Access denied：仅明确常驻托管时允许 worker 留在任务 Job；真实 Job 回归测试覆盖拒绝与成功路径。
- Mac 官方 GUI CLI 读取 netmap 触发崩溃：改由限时 LocalAPI 读取新鲜元数据。
- Mac 原生最后通信时间陈旧：收发字节增量补充需求判断，并排除自身探测流量及时间戳。
- 后台长任务误报离线：独立健康心跳。
- 后台重启后重放已处理请求：终态与 idle / observing 的已处理请求不重复执行。

## 自动检查

`./scripts/check` 覆盖格式、全项目 race 测试与 vet。测试涉及授权与身份隔离、原子配置与互斥、取消和退避、同 socket 预验证及有序首发、探测事务老化、候选拒绝、承载与租期、平台 worker 生命周期及业务判据。

`./scripts/build` 生成五个平台的产品和兼容工具共十个二进制；`scripts/package.py` 生成五个带部署文件的测试包。校验清单使用 SHA256。macOS amd64 和 Linux arm64 仅有构建验证。

部分集成测试使用模拟原生路径、真实 TCP / UDP 协调和完整业务验证器。它们不模拟真实 NAT，不能替代现场验收。

## 实际限制

当前现场成果适用于已测试网络中的 Mac / Windows 客户端与具有公网物理 IPv4 的 Linux 响应端。单次成功不代表跨网络成功率或所有 NAT 均能打洞。

整机重启、实际睡眠唤醒、多网络长期运行及新 Wi-Fi 自动恢复尚未完整现场验收。原生公网 IPv6 SSH 可达性与 Tailscale IPv4 辅助会话是独立事项。后续测试按[对照实验规程](experiment-protocol.md)实施。
