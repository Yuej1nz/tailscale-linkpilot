# 验收范围与结果

验证日期：2026-10-04，Asia/Shanghai。当前产品版 `0.8.0-service-controls`，兼容核心版本 `0.4.0-windows-client`。原始部署配置、实际地址、节点 ID、账号与完整报告保留在本机，公开仓库只记录范围及结论。

## 实机结果

以下单节点新打洞现场验收来自 Windows 0.5 / Mac 0.6 的既有记录。版本 0.7 的全节点调度验证单独记录，不把历史成功当作新版本的多节点现场验收。

| 组合 | 已证明的结果 |
| --- | --- |
| Windows amd64 → Linux amd64 | 用户计划任务运行；真实中继状态下，无新增立即优化请求，由后台触发新会话并完成三次业务验收；辅助会话保留与续期 |
| macOS arm64 → Linux amd64 | 用户 LaunchAgent 与独立受限采集授权；无新增立即优化请求，由持续中继触发新会话；三次业务及承载计数全部通过 |
| Mac 后台重启 | 同一辅助会话继续运行，成功报告与已处理请求保留；独立探测仍为 direct；默认租期在满足条件时续期 |
| Linux 多设备协调 | Mac 与 Windows 授权隔离，授权撤销和恢复无需重启整个服务 |

Mac 自动试次结果为 `direct_via_new_local_session`。前两个候选没有证明 UDP 往返，关闭且未启用原生转发；第三个候选成功。三次数据大小均为 64 KiB，双方原生路径和两端加密业务计数通过。后续客户端独立探测约 12 ms；服务端探测仍有时延波动。

原有手动工具曾先建立健康直连。产品的保留验收记录 `optimized=false`，随后只清理这对设备的旧辅助会话，重新确认中继，再验证新产品自动恢复。这两个阶段分别记录，不把已有直连算作新打洞成果。

## 全节点调度回归

版本 0.7.0 的自动测试覆盖动态发现、离开列表、重命名、名称歧义、身份绑定、暂停和排除持久性、无隐式授权、空闲节点无主动 IO、长任务期间继续观察其他节点、排队请求保留、任务串行、公平轮转、探测配额、权限与能力门控及换网取消。

真实本地 UDP socket 与 Unix IPC 测试覆盖多个节点 worker 同时存活、旧单会话兼容、定向停止不影响其他节点、十六个承载的资源上限和运行路径验证。完整自动触发集成测试使用真实 TCP 协调与三次业务验证，原生路径仍为合成观测。

本轮 `scripts/check` 的全项目竞态与静态检查通过，五个平台共十个二进制和五个测试包构建通过。Mac / Windows 已更新并启用全节点模式，每端跟踪四个可见目标；实机验证了单节点暂停在重复选择全部节点后保留，入站协调授权未增加。Windows 0.7 后台在没有新立即优化请求时建立新 IPv4 辅助会话，结果 `direct_via_new_local_session`，三次 64 KiB 业务、双向路径及双方承载字节增量通过。Mac 当前路径可直连，但其复测未证明所选旧辅助会话承载，不计为本次优化成功。

Mac / Windows 原生 IPC 回归均通过，Windows 还验证了不可脱离 Job 中的托管子进程启动。后续探测观察到路径会波动，不能把一次成功当作长期稳定。

多节点真实 NAT 同时打洞成功率和长期运行尚未验收；上述测试不代表所有节点都可以直连。

## 统一后台管理验收

版本 0.8 增加 Mac / Windows / Linux 通用的 `start / stop / restart`。Windows 使用 Task Scheduler COM 接口登记和控制任务，当前机器缺失的 ScheduledTasks CIM provider 不再阻断安装。日常启停不重新安装或扩大协调授权。Windows 后台退出错误写入用户配置目录的 `daemon.log`。

三台实机已更新到相同版本，并分别验证：连续两次 start 保持同一后台 PID；stop 后 status 立即离线，重复 stop 成功；start 恢复健康；restart 更换 PID 并发布新版本和新鲜心跳。配置文件内容比较确认目标、暂停、排除和入站授权保留。Mac / Windows 的全节点模式及四个已选目标仍保留；Linux 的原有响应端授权保留。三台机器测试结束后后台均运行。

Windows 实机还拒绝了使用另一配置目录停止当前登记任务的调用，当前后台保持在线。回归测试覆盖同样的配置范围限制、重复操作、失败停止不删除活跃心跳、旧进程锁未释放时禁止启动、旧心跳或另一身份不算启动成功，以及参数校验不依赖原生 Tailscale 在线。

这轮只验收服务管理与配置保留，没有将服务重启或现有 direct 状态计为新的 NAT 打洞成果，也不代表实际重新登录、整机重启或长期故障恢复已完成验收。

## 已修复问题

- Windows 计划任务的 Job 不允许子进程脱离，旧独立 worker 启动返回 Access denied：仅明确常驻托管时允许 worker 留在任务 Job；真实 Job 回归测试覆盖拒绝与成功路径。
- Mac 官方 GUI CLI 读取 netmap 触发崩溃：改由限时 LocalAPI 读取新鲜元数据。
- Mac 原生最后通信时间陈旧：收发字节增量补充需求判断，并排除自身探测流量及时间戳。
- 后台长任务误报离线：独立健康心跳。
- 当前原生直连探测覆盖失败的优化结果：以独立完成记录绑定请求和业务判据，手动命令不再依赖当前路径状态。
- 后台重启后重放已处理请求：终态与 idle / observing 的已处理请求不重复执行。

## 自动检查

`./scripts/check` 覆盖格式、全项目 race 测试与 vet。测试涉及授权与身份隔离、原子配置与互斥、取消和退避、同 socket 预验证及有序首发、探测事务老化、候选拒绝、承载与租期、平台 worker 生命周期及业务判据。

`./scripts/build` 生成五个平台的产品和兼容工具共十个二进制；`scripts/package.py` 生成五个带部署文件的测试包。校验清单使用 SHA256。macOS amd64 和 Linux arm64 仅有构建验证。

部分集成测试使用模拟原生路径、真实 TCP / UDP 协调和完整业务验证器。它们不模拟真实 NAT，不能替代现场验收。

## 实际限制

当前现场成果适用于已测试网络中的 Mac / Windows 客户端与具有公网物理 IPv4 的 Linux 响应端。单次成功不代表跨网络成功率或所有 NAT 均能打洞。

整机重启、实际睡眠唤醒、多网络长期运行及新 Wi-Fi 自动恢复尚未完整现场验收。原生公网 IPv6 SSH 可达性与 Tailscale IPv4 辅助会话是独立事项。后续测试按[对照实验规程](experiment-protocol.md)实施。
